# 테스트와 알려진 한계

## 공개 테스트 기준

2026-11-12 Apple Silicon 환경에서 새 소스 ZIP을 풀어 기본 `bash build-app.sh`로 배포용 빌드·번들 서명·검증을 완료했습니다. 로컬 자동 검사 196개(크기·프로세스 28개, 저장 공간·보호 경로 43개, 앱 흐름 41개, 사용자 여정 58개, 후보·개선 사항 26개)가 통과했습니다.

이 검사는 사용성 만족도, 모든 macOS 버전 지원, 모든 파일의 삭제 안전성을 보증하지 않습니다. 실제 화면에서는 후보 탐색·화면 복귀·빈 검색 결과·폴더 분석·중단 및 재시도 등을 확인했지만, 현재 버전의 설치/업데이트/복구 통합 검사는 다시 실행하지 않았습니다. 과거 일회용 설치 데이터 검사와 실제 사용자 앱의 삭제/복원 검증은 구분합니다.

## GitHub에서 확인된 문제

2026-11-12 공개 태그의 원격 검사에서는 앱 빌드·서명 검증과 앞선 검사 112개가 통과했지만, 사용자 여정 검사의 **분석 중단 후 부분 결과 보존 확인**에서 실패했습니다. 로컬 검사 통과와 별개로, 원격 전체 검사는 통과하지 못한 상태입니다.

[해당 검사 결과](https://github.com/Rayeonjin/Uncomew/actions/runs/43236910420)를 참고해 주세요. 이번 한국어 문서 정리에서는 앱 코드나 이 테스트를 수정하지 않았습니다.

## 직접 검사하기

```bash
bash test-core.sh
bash test-workflow.sh
bash test-flow.sh
bash test-journeys.sh
bash test-improvements.sh
```

일반 검사는 사용자 파일을 휴지통으로 옮기지 않습니다. `test-journeys.sh`는 합성 메타데이터로 주요 여정을 세 번 반복합니다. 임시 경로에서 안전 검사를 실행하는 방법은 [빌드 안내](BUILDING.md#임시-경로에서-개발-테스트하기)를 참고하세요.

GitHub Actions는 빌드와 위 검사를 실행합니다. 결과는 저장소의 Actions에서 확인할 수 있습니다. 자동 검사가 통과해도 실제 화면 확인을 대신하지 않습니다.

별도 선택 검사:

```bash
bash Tests/Installation/test_installation.sh
bash test-improvements.sh --benchmark
bash test-improvements.sh --trash
```

설치 검사는 Uncomew를 종료한 뒤 실행하세요. `--trash`는 일회용 테스트 앱을 실제 휴지통으로 이동·복원합니다. 일반 자동 검사에서는 실행하지 않습니다.

## 알려진 한계

- Intel 및 macOS 13 이상 모든 버전의 실기 검증은 완료하지 않았습니다.
- 클라우드·외장·네트워크 파일 공급자와 대량 파일에서 성능·응답이 달라질 수 있습니다. 내용 읽기 없이 메타데이터를 확인하더라도 공급자 응답이 지연될 수 있습니다.
- 스캔에는 항목 수·깊이·디렉터리 응답 시간 한도가 있으며, 결과가 불완전하면 표시합니다.
- APFS 공유 블록과 논리/점유 크기의 차이 때문에 목록의 크기를 확보 가능량으로 해석하면 안 됩니다.
- 앱 사용 기록이 없는 것은 미사용이 아닙니다. 관련 경로의 앱 식별자 일치는 독점 소유를 증명하지 않습니다.
- 파일 식별·실행 상태 검사와 실제 휴지통 이동은 하나로 묶여 동시에 보장되는 작업이 아닙니다. 검사 직후 외부 파일 변경이 발생하는 경우를 완전히 배제하지 못합니다.
- 앱 내 복원은 현재 실행의 기록만 사용하며 기존 파일을 덮어쓰지 않습니다. 휴지통이 외부에서 비워진 경우 복원할 수 없습니다.
- 스캔 비교, 중복 파일 탐지, Quick Look은 아직 구현하지 않았습니다.
